📋 WHAT'S FIXED IN THIS VERSION
================================================================================

✅ PROBLEM 1: DE-Erkennungslogik (Classification Logic)

   Issue: German IPTV links incorrectly classified into output files
   - Links with ONLY German Live TV wrongly marked as "both" (implies movies)
   - Misclassified into free_links.txt instead of free_links_TVonly.txt

   Root Cause: Line 2727 logic flaw
   - OLD: category = "both" if (vod_de or not vod_has_content) else "tvonly"
   - If no German VOD AND no VOD available → incorrectly marked as "both"

   Solution: Corrected classification logic
   - NEW: category = "both" if vod_de else "tvonly"
   - Properly distinguishes:
     * "both": German Live TV + German Movies → free_links.txt
     * "tvonly": German Live TV only → free_links_TVonly.txt

   Impact: ✅ Correct output file routing, accurate German content detection


✅ PROBLEM 2: Re-Check Mode False Positives

   Issue: Many valid links marked INVALID during re-checks
   - Links worked when manually tested
   - Previously validated in initial scans
   - Just exceeded timeout threshold

   Root Causes & Solutions:

   2.1 TCP Pre-Check Timeout Too Strict
       - Original: 3.5 seconds
       - Solution: Increased to 5.0 seconds for re-check mode
       - Impact: Slow servers no longer timeout prematurely

   2.2 API Call Timeout Too Strict
       - Original: 10 seconds
       - Solution: Increased to 15 seconds for re-check mode
       - Impact: Slow server responses handled correctly

   2.3 Sample Stream Check Overhead
       - Problem: Unnecessary checks on already-validated links
       - Solution: Disabled sample-check in re-check mode
       - Impact: Faster re-check processing

   2.4 Duplicate Link Entries After Re-Check
       - Old Problem: mark_invalid_links() appended comments
       - Result: Same link appeared 3x (valid + 2 RECHECK comments)
       - Solution: Rewrote to read file, replace duplicates with single comment
       - Impact: No more duplicate entries

   2.5 URL Parsing with ** Prefix
       - Problem: Links like **http://host:port/... failed to parse
       - Cause: urlparse treats **http as scheme
       - Solution: Created _extract_url_from_line() to strip prefixes first
       - Impact: Copy-pasted links now work correctly
